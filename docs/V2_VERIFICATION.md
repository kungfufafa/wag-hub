# V2 implementation verification — 2026-09-21

## Follow-up review fixes

The six accepted review findings have been corrected:

- Offline `append` arrivals are retained, with durable provider-identity
  deduplication across reconnects, restarts, acknowledgement, and crash windows.
- Failed or timed-out media retrieval no longer blocks unrelated events,
  including behind more than 100 pending attachments. Pending media cannot be
  prematurely acknowledged, and its retry state survives restart.
- Inactive/deleted installations and incomplete callbacks cannot monopolize
  webhook batches; pending deliveries resume on reactivation within the retry
  window, and expired retries remain replayable until retention expires.
- Migrated dashboard controls use authoritative lifecycle operations and
  generations, including QR/pairing reads, callbacks, and single/bulk deletion.
- Both repositories require PHP `^8.4.1`; wag-hub's image uses PHP 8.4 and CESA's
  CI selects PHP 8.4. Deployment examples use the same runtime. Only root platform
  metadata and its Composer content hash changed in the lockfiles; package
  versions were preserved.
- The deployment includes a separate `default` worker for legacy messages,
  with a 360-second job timeout, 390-second shutdown grace, and 420-second retry
  interval. A database-backed queue test consumes an accepted legacy message and
  verifies an idempotent replay does not enqueue or send it again.

## Real CESA dump rehearsal

Restored `cesa.gz` into a separate, socket-only MySQL instance. No application or
production database was used. The dump had 91 tables, 36 users, one soft-deleted
WhatsApp account with ID 1, and zero recruitment notification-delivery rows.
The additive migrations completed, yielding 94 tables with those records and IDs
preserved. Re-running the migrations made no changes.

A transaction-only smoke test temporarily made that legacy account active,
projected a hub session using `external_reference=rekrutmen-1`, verified the same
local ID, repeated the projection without duplication, and created a new account
without a phone number. The transaction rolled back, preserving the original dump
fixture. Existing nonempty notification history is covered by application tests;
this particular dump contains no delivery rows to exercise that case.

Fresh hub schema installation on MySQL also exposed two older migration issues:
dropping an index supporting a foreign key, and an autogenerated index name longer
than MySQL's limit. Both migrations now complete successfully on MySQL and SQLite.
